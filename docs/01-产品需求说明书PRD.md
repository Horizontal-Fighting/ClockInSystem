## 1. 项目背景与目标

### 1.0 目标用户画像（已确认：小学阶段 6-12 岁）

年龄段锁定后，产品设计有几个必须跟着调整的地方——**6-12 岁和 3-6 岁启蒙是两个物种**：

| 维度 | 6-12 岁小学生（本项目） | 3-6 岁启蒙（杨桃妈妈主战场） |
|---|---|---|
| 认知与自主性 | **有自主意识，可独立操作**，知道自己读得好不好 | 完全依赖家长 |
| 核心驱动力 | **同伴比较 + 成就感 + 被老师看见** | 游戏化、贴纸、家长表扬 |
| 挫败阈值 | 较高，能接受"这句没读好，再来一次" | 极低，一次低分就可能放弃 |
| 内容形态 | 拼读规则、句型、分级读物、短文 | 儿歌、亲子口语、绘本磨耳朵 |
| 单次时长 | 3-8 秒（句子）/ 20-40 秒（段落） | 1-3 秒 |
| UI 风格 | **学习工具感**，可适度保留趣味，但忌"幼态化" | 大色块、卡通、动物形象 |
| 家长角色 | **监督者 + 查看者**，不需要代操作 | 共同学习者、代操作者 |

**由此产生的三条设计结论**：

1. **6-12 岁跨度大，必须分两个学段设计**，否则一年级和六年级用同一套东西必然有一头不讨好：
   - **低学段（6-8 岁，一二年级）**：拼读规则为主，趣味性强，参考 L1-L4 级别
   - **高学段（9-12 岁，三至六年级）**：句型、短文、分级读物为主，强调**进步可视化与同伴激励**，参考 L5-L6 级别
2. **排行榜从 P2 提到 P1**：这个年龄段同伴驱动效果显著，但要支持机构级开关（部分机构不希望竞争）。
3. **账号可简化但家长端不能省**：孩子能自己打卡，但**家长必须能看到点评和成长报告**——续费决策人是家长。

> ⚠️ **合规提示**：6-12 岁**全部属于《个人信息保护法》第 31 条的"不满 14 周岁"儿童范畴**，儿童个人信息的全套合规要求（见 `02` 文档第 7 章）一个都不能少，比 3-6 岁场景没有任何放松空间。

### 1.1 背景

小学阶段英语拼读与口语练习的核心痛点不是"没内容"，而是**练了没人听、听了没反馈**：

| 痛点 | 现状描述 |
|---|---|
| 跟读无人纠音 | 孩子每天读，家长分不清对错，一周后进了老师才知道发音固化了 |
| 教师工作不可扩展 | 一个老师带 100 个学生，逐一听录音 → 每天 3-4 小时，只能挑样本听 |
| 进度不可见 | 家长看不到系统性成长轨迹，只剩"坚持打卡 30 天"这种模糊成就感 |
| 内容组织散 | 素材在网盘/群里，布置作业靠发链接，学生交作业靠群里的语音，无法归档 |

### 1.2 产品目标

用 **AI 语音评测替代教师的重复听音劳动**，让老师只做机器做不了的部分（针对性点评、鼓励、纠偏），从而把"一个老师带 20 人"扩展到"一个老师带 200 人"且质量不降。

一句话概括：**它是一个「布置 → 跟读 → AI 打分 → 教师点评 → 成长可见」的完整闭环工具，而不是一个内容播放器。**

### 1.3 成功指标（建议，待确认）

| 指标 | 定义 | 目标值 |
|---|---|---|
| 学生周活跃打卡率 | 每周至少打卡 1 次的学生 / 在册学生 | ≥ 60% |
| 任务完成率 | 已交作业数 / 已布置任务数 | ≥ 75% |
| AI 自动通过率 | AI 评分 ≥ 80 分无需教师重听的比例 | ≥ 70%（衡量引擎可用性） |
| 教师点评时效 | 提交到点评的平均时长 | ≤ 24h |
| 教师单人次处理耗时 | 完成一条点评的平均耗时 | ≤ 60s（当前人工约 180s） |

## 2. 参考产品分析（杨桃妈妈）

> 说明：以下为公开资料整理（公众号、小程序、第三方平台介绍），用于提炼可借鉴模式，**不涉及其未公开的商业数据**。

### 2.1 其模式要点

| 维度 | 做法 | 借鉴价值 |
|---|---|---|
| 内容组织 | 按主题分栏目：亲子英语、词汇屋、英文儿歌、分级绘本精讲（RAZ/培生）、单词简笔画、双语故事 | 高 — 内容需按"栏目/路线"而非单点组织 |
| 跟读设计 | 提供**慢速 / 常速**变速跟读音频，降低模仿门槛 | 高 — 变速播放是剛需，必须做 |
| 更新节奏 | 固定频次推送（周一至周六每日更新），形成稳定预期 | 高 — 打卡任务要有节奏，不能随机 |
| 社群运营 | 微信群 + 分班 + 班长催课 | 高 — 产品化为「班级 / 小组 / 打卡提醒」 |
| 激励机制 | 完课彩蛋、周全勤彩蛋 | 中 — 产品化为「连续打卡勋章 + 彩蛋解锁」 |
| 家长角色 | "让父母成为孩子最好的英语老师"，配套中文解释与场景句型 | 高 — 家长端需提供"我也不会英语"的兜底支持 |
| 内容分发 | 公众号内容 + 小程序落脚 | 中 — 可通过微信生态自然衔接 |

### 2.2 我们要做的差异

杨桃妈妈本质是**内容 + 社群**，靠人工维持。我们补上它缺的三件事：

1. **AI 音素级纠音** — 明确指出"cat 里的 /æ/ 发成了 /e/"，这是人工难以规模化提供的；
2. **结构化班级管理** — 分级 / 分组 / 作业布置 / 提交追踪，替代微信群里的混乱；
3. **数据化成长可见** — 打卡日历、错误音素云、词汇掌握度，让坚持有客观证据。

### 2.3 同类跟读产品界面对标（2026-09-17 实拍截图分析）

> 对象：某同类小程序的「单词纠音」页面（杰哥提供实拍截图）。结论：**大框架与我们高度一致，但其把"音素级反馈"做成了首屏核心体验，这验证了我们 Spike 的方向，同时暴露两处设计差距。**

**其页面结构**（单词 pencil 为例）：

```
练习页：进度 1/7 · 生词本入口
  ├ 单词按音节拆分着色显示：pen·cil（不同音节不同色）
  ├ 中文释义「铅笔」+ 美式音标 /ˈpen·səl/ + 示范播放 + 倍速
  ├ ★ 字母-音素一一对应块：p→/p/ e→/e/ n→/n/ c→/s/ i→/ɪ/ l→/l/
  ├ 「自然拼读」/「示范朗读」模式切换
  └ 底部：听示范 / 重新跟读 / 我的跟读（回放）

结果弹层（跟读后）：
  ├ 总分 40 分
  ├ ★ 每个音素的得分色块：26 84 78 82 98 0（红<60 / 黄60-79 / 绿≥80）
  ├ 文字诊断："pencil 中 /l/ 发音有误" + 「立即纠音」按钮
  └ 我的跟读 / 重新跟读 / 下一个
```

**与我们设计的逐项对照**：

| 参考产品功能 | 我们的设计 | 差距与动作 |
|---|---|---|
| 听示范→跟读→评分→重读/下一个 | F2-3 + F3-1~F3-6 | ✅ 已覆盖 |
| 结果页逐音素得分色块 + 文字诊断 | F3-7 只有错词高亮 + 薄弱音素提示 | ⚠️ **补进 MVP**（F3-8 拆分，见 F3-8a） |
| 音节拆分着色 + 字母-音素对应块 | F2-4 仅有"音标分解 + 口型图"概念 | ⚠️ F2-4 细化 + `material` 表补字段（见 `02` 文档 material 表） |
| 「我的跟读」vs「听示范」对比 | F3-9（原排 V1.2） | ✅ 已规划，**提入 V1.1** |
| 生词本 | 无 | 新增 F2-6（P2） |
| 诊断结果「立即纠音」跳转 | 无此闭环 | 新增 F3-11（P2），与课件体系衔接 |

> **两条战略级确认**：
> 1. **音素级纠音就是这类产品的卖点，不是增强项**——参考产品把它放在结果页首屏。
>    我们 Spike 正在验证的 `PhoneInfos` 音素命中率正是支撑这个体验的数据，方向踩对。
> 2. 差异化优势仍然成立：我们有参考产品没有的**教师点评 + 班级任务体系**，
>    它是"个人练习工具"，我们是"机构教学闭环"。两者不冲突。

### 2.4 明确不做的边界（MVP 阶段）

- ❌ 直播 / 真人外教对话
- ❌ 自研语音评测引擎（直接采购成熟云服务）
- ❌ 复杂的内容编辑器（后台以"素材录入 + 打包"为主）
- ❌ 支付与购课（MVP 走线下收费，系统只做"在读/已结业"状态管理）

## 3. 用户角色与权限

| 角色 | 入口 | 核心诉求 | 关键权限 |
|---|---|---|---|
| **学生** | 微信小程序（儿童版 UI：大按钮、少文字、多图形） | 好玩、简单、立刻看到反馈 | 查看任务、录音、听自己的录音、看星星、看日历 |
| **家长** | 同一小程序（家长模式，密码切换） | 知道孩子读得对不对、老师说什么、要不要催 | 全部学生权限 + 查看点评 + 代传 + 成长报告 + 接收提醒 |
| **教师** | 微信小程序（轻量）+ PC 后台（重操作） | 少做重复劳动、批量处理、不被漏掉 | 管理所带班级、布置任务、待点评队列、点评、查看统计 |
| **教研/内容运营** | PC 后台 | 素材批量录入、分级挂接、打包成任务 | 素材库、级别字典、任务包、范读音频上传 |
| **管理员** | PC 后台 | 全局掌控 | 账号、班级、教师分配、数据看板、系统配置、日志 |

> **设计要点**：学生与家长共用小程序，不做两个小程序。原因是微信小程序的账号体系是手机号，孩子通常没有手机，实际使用者是家长（"家长拿着手机，孩子对着读"）。角色切换用本地 PIN 码，不做复杂的多账号。

## 4. 核心业务流程

### 4.1 打卡主闭环

```
[教师] 备课：选择素材 → 打包成任务包 → 指定班级/小组 → 设定截止日期、是否必做
                                    ↓
                            到点发布，推送订阅消息
                                    ↓
[学生] 打开小程序 → 今日任务卡片 → 听范读（慢速/常速）→ 按住跟读（录音）
                                    ↓
                    上传录音 → 服务端调用语音评测 → 返回分数 + 音素诊断
                                    ↓
            即时反馈页：星星数 + 读错的词高亮红色 + 薄弱音素提示 + 鼓励动画
                                    ↓
                        提交进「教师待点评队列」
                                    ↓
[教师] 工作台 → 待点评列表（AI 已预标：哪些需要重点听）→ 播放录音 + 看 AI 诊断
                                    ↓
            语音点评（≤60s）+ 快捷标签 + 文字补充 + 是否要求重做
                                    ↓
[家长] 收到"老师点评了"通知 → 查看详情 / 一键转发到朋友圈/群
                                    ↓
                    写入成长档案 + 更新连续打卡天数 + 更新掌握度画像
```

### 4.2 分级定级流程（新生入学）

```
注册 → 填写年龄/年级/是否有基础 → 做定级测评（约 15 题，5 分钟）
     → AI 打分 → 系统给出建议级别（L1~L6）→ 老师确认/调整 → 自动分入对应班级
     → 生成初始「薄弱音素档案」，作为后续纠音依据
```

### 4.3 状态流转

**任务状态**：草稿 → 已发布 → 进行中 → 已截止 → 已归档
**打卡状态**：待打卡 → 已提交（待点评）→ 已点评 / 需重做 → 已完课
**学生状态**：待报名 → 在读 → 请假 → 已结业 → 已流失

### 4.4 组织模型（已确认）

```
租户 / 机构 Tenant（培训机构，自用，不面向校方）
   │
   ├── 教师 Teacher（一个机构有多名老师）
   │      └── 班级 Class（一名老师可带多个班级）
   │             └── 学生 Student（一个班级多名学生）
   │                   └── 家长（1 个家长可绑定多个孩子）
   │
   └── 班级也可不挂老师，由机构管理员直接管理
```

| 规则 | 说明 |
|---|---|
| 租户 = 培训机构 | 机构自用，**不向校方开放** |
| 一租户多教师 | 每个机构可以有若干名老师 |
| 一教师多班级 | 一名老师可同时带多个班级 |
| 一租户多班级 | 机构层面统一管理所有班级，可按年级/程度分组 |
| 学生与班级 | 学生归属于某个租户下的班级；**同一学生理论上可加入同租户的多个班级**（如常规班 + 提高班），按实际需要开放 |
| 教师与班级 | 建议 **N:1（一个班一位主讲老师）**，同时允许助教/多名教师关联同一班级 |

### 4.5 学生入班流程（已确认：扫码为主）

```
[教师] 在教师端/后台生成「班级二维码」（含 group_id + tenant_id，可设有效期）
                ↓
        发到微信群 / 打印张贴 / 课堂展示
                ↓
[家长] 小程序扫码 → 自动识别班级 → 选择/创建孩子档案
                ↓
        阅读并勾选《儿童个人信息处理规则》（首次必填）
                ↓
        提交入班申请  →  默认自动通过（可切换为老师审核）
                ↓
[教师] 班级成员列表实时更新，可手动移除/调整
```

**设计要点**：

- 二维码内容建议为**短链 + token**，而非明文 group_id（避免被猜到后批量加入）
- 二维码**可设有效期**（如 7 天）与**可撤销**，过期后旧码失效
- 后台仍保留「手动添加学生」与「批量导入」作为兜底（老师代操作场景）
- **跨租户防护**：扫码时必须校验当前登录用户与二维码所属租户一致，否则提示"该二维码不属于您所在的机构"

## 5. 功能需求详述

### 5.1 C 端 · 学员/家长小程序

#### F1 注册与账号

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| F1-1 | 微信一键登录（**仅取 openid**） | P0 | wx.login 换 openid。**不调用 `getPhoneNumber`，不采集手机号**（数据最小化，见 F1-8） |
| F1-2 | 学生档案创建 | P0 | **仅两项：昵称 + 系统预置头像**。不采集真实姓名、生日/年龄、性别、年级、学校、位置、真人照片（合规硬约束，见 `02` 文档 7.0）；一个家长可绑定多个孩子 |
| F1-3 | **监护人知情同意** | P0 | 首次创建学生档案时必须勾选《儿童个人信息处理规则》，服务端留存同意记录（含时间戳、版本号、IP） |
| F1-4 | **扫码加入班级（主入口）** | P0 | **老师出示班级二维码 → 学生/家长扫码 → 确认加入**。这是最主要的分班方式，替代邀请码 |
| F1-5 | 学生/家长模式切换 | P1 | 学生模式隐藏数据看板、教师点评原话等对儿童不宜直接展示的内容 |
| F1-6 | 切换孩子 | P0 | 顶部头像下拉切换 |
| F1-7 | **账号登录（不限制设备）** | P0 | 除微信登录外，支持**账号+密码登录**（用户名 + 密码，**不强制绑手机**），且**不限制登录设备数**。适用于：孩子用家长的旧手机/平板打卡、家里多个设备轮换、无微信的场景 |
| **F1-8** | **数据最小化（合规硬约束）** | **P0** | 学生档案**只有昵称 + 系统预置头像**。不采集：真实姓名、生日/年龄、性别、年级、学校、位置、真人照片、手机号、任何生物特征。详见 `02` 文档 7.0 |

> **F1-7 设计要点**：账号体系采用「微信身份 ↔ 业务账号」绑定模型。微信登录是便捷入口，账号密码是通用入口，两者指向同一个 `user` 记录。不限制设备意味着**不做设备指纹/设备数校验**，但要有基础的异地登录提醒与会话管理能力（同一账号可多端在线，token 不互斥）。
>
> **F1-8 说明**：头像**只能从 24 个系统预置卡通形象中选择**，产品上**不提供上传真人照片的入口**（不是"不建议"，是"不给入口"）。小程序端**不得申请** `getLocation`、`getPhoneNumber`、相册/相机权限。
>
> ⚠️ **但有一个躲不掉的例外：录音**。学生的声音属儿童个人信息，因此**监护人同意流程（F1-3）不能省**——详见 `02` 文档 7.0 的说明。

#### F2 首页 · 今日打卡

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| F2-1 | 今日任务卡片 | P0 | 显示老师今日布置的内容包，含封面、标题、条目数、预计时长 |

### 5.3 管理后台（PC Web）

#### F7 课件 · 知识点语音讲解（已确认形态）

> **形态已确认：文字 + 语音解读，不涉及视频。** 课件是老师在小程序端给学生看的「知识点讲解页」——一段文字配一段老师的语音解说，学生边看边听，听完再去打卡。

**与素材（material）的区别**：

| | 素材 material | 课件 courseware |
|---|---|---|
| 用途 | 被朗读、被评测的对象 | 被阅读、被收听的讲解内容 |
| 是否参与评测 | 是（作为 ref_text） | **否**（不产生评测调用与费用） |
| 内容形态 | 单一文本（单词/句子/段落） | 多个内容块的有序组合 |
| 是否可变速 | 是（0.6/0.8/1.0x 三档） | 否（讲解音频通常较长，仅支持 1 档，可加速播放） |

**课件结构**：一个课件 = 若干**内容块（Block）**的有序列表，块类型共 4 种：

| 块类型 | 内容 | 说明 |
|---|---|---|
| 文本 | 富文本（标题/正文/重点高亮） | 讲解正文 |
| 图片 | 单图 | 口型图、拼读规则示意图等 |
| 讲解音频 | 一段 mp3 | **核心**：老师的语音解读，配在文本下方 |
| 素材引用 | 引用素材库某条 | 内嵌一个可播放的单词/句子卡片，讲完规则立刻听例子 |

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| F7-1 | 课件浏览 | **P0** | 小程序端按「文字 + 语音」逐块阅读，音频可播放/暂停/拖动 |
| F7-2 | **课件与任务关联** | **P0** | 课件挂在打卡任务上：任务详情页顶部「先看讲解 → 去打卡」。**课件没有独立入口，必须挂任务才有入口**——所以这条与 F7-1 是绑定的，要么都做要么都不做 |
| F7-3 | 课件来源 | **P0** | **独立内容类型**，由机构后台自建（与素材库平级，共享租户隔离与自建版权）。后台编辑器见模块 C5 |
| F7-4 | 播放体验增强 | P2 | 连续播放（听完一块自动下一块）、0.8/1.0/1.2x 倍速、断点续听 |
| F7-5 | 学习进度与强制前置 | P2 | 记录「已读至第几块 + 是否已听完」，支撑强制前置校验与教师端查看 |
| F7-6 | 语音点评复用 | P2 | 老师点评时可引用课件某一段讲解音频，避免重复讲解 |

> **优先级说明**：课件是需求清单的第 1 项，且确认无视频后实现成本可控（纯展示 + 结构化块编辑器，约 +0.5 周），因此**核心三项纳入 MVP**。但 F7-4/5/6 属增强项，放 V1.1——尤其「强制前置」默认关闭，MVP 不做进度记录也不影响闭环。

> **设计判断**：课件**不强制前置**（F7-5 默认关闭）。6-12 岁孩子看到「必须听完 5 分钟才能打卡」会直接放弃，把讲解做成"就在手边的参考资料"转化率更高。是否强制由老师在布置任务时决定，能力留着，默认不开。

> **成本提示**：讲解音频是**纯内容资产，不走语音评测**，不产生第三方评测费用，仅占 COS 存储（估算见 `02` 文档 3.4）。

#### 模块 B · 分级体系（Level）

针对 **6-12 岁小学阶段**重新设计的九级体系（后台可配置），覆盖两个学段：

**低学段 · 拼读筑基（6-8 岁，一二年级）**

| 级别 | 名称 | 内容形态 | 评测模式 |
|---|---|---|---|
| L1 | 字母音 Letter Sounds | 26 个字母 + 常见发音，单音素跟读 | 单词模式 `eval_mode=0` |
| L2 | 短元音 CVC | cat / dog / big 三字母词 | 单词模式 |
| L3 | 辅音连缀 & 长元音 | bl-/st-/ai/ee/oa 等 | 单词模式 |
| L4 | 双音节 & 常见词族 | -at / -og 家族、双音节词 | 单词模式 |

**高学段 · 句型与阅读（9-12 岁，三至六年级）**

| 级别 | 名称 | 内容形态 | 评测模式 |
|---|---|---|---|
| L5 | 短句朗读 | 6-10 词短句、日常口语 | 句子模式 `eval_mode=1` |
| L6 | 长句与复合句 | 10-20 词，含从句 | 句子模式 |
| L7 | 段落朗读 | 30-80 词段落 | 段落模式 `eval_mode=2` |
| L8 | 分级读物 | 分级绘本整篇跟读 | 段落模式 |
| L9 | 自由表达（V2.0） | 看图说话、主题复述 | 自由说 `eval_mode=3` |

**配套规则**：

- 定级测评按学段走不同题库（低学段拼读题、高学段朗读题），约 15 题 / 5 分钟
- 升级规则可配，如"连续 5 次 ≥85 分自动升入下一级"，也支持教师手动调整
- 级别 ↔ 素材 ↔ 任务包挂接；**同一班级内可存在多个级别**（分层教学刚需）

> ⚠️ **成本提示**：L7/L8 的段落模式下，腾讯云按「每 20 单词计 1 次调用」计费，一段 60 词的绘本 = 3 次调用。**长段落建议用段落模式（3 次）而非拆成 5 个句子（5 次）**，但会牺牲反馈粒度——教研需按内容重要性取舍，详见 `03` 文档第 2 节。

| G4 | 成本监控 | P1 | 评测资源包余量、并发峰值、单学员成本趋势，低于阈值告警 |
| G5 | 租户数据导出 | P2 | 按租户打包导出全量数据（合规与迁移需求） |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| **性能** | 录音上传后评测结果返回 ≤ 5s（P95）；小程序首屏 ≤ 2s；后台列表页 ≤ 1s |
| **并发** | 支持单租户 500 学员同时使用；晚 19:00-21:00 为高峰期。**注意：并发数直接产生费用**（腾讯云超 50 并发按 ¥30/个/月计），架构上必须用队列削峰，见 `02` 文档 1.4 与 `03` 文档第 5 节 |
| **规模** | 三年演进目标：2,000 → 6,000 → 10,000 学员；**三年内不分库分表**，靠分区 + 预聚合 + 冷热分层支撑（见 `02` 文档 3.4） |
| **可用性** | 核心打卡链路可用性 ≥ 99.5%；第三方言评测故障时**不得阻断打卡**（降级：先记录，事后补评） |
| **音频** | 单文件 ≤ 5MB；采样率 16kHz、16bit、单声道（评测引擎要求）；**服务端统一转码为 32kbps mp3 存储** |
| **数据安全** | 录音文件私有读 COS + 临时签名 URL 访问，URL 有效期 ≤ 2h；**按租户分目录存储** |
| **租户隔离** | 所有查询强制带 `tenant_id`；CI 须包含「跨租户越权」自动化测试（见 `02` 文档 1.4.2） |
| **合规** | 见 `02-技术架构与数据设计.md` 第 7 章（未成年人信息保护，强约束）。**6-12 岁全部适用** |
| **兼容** | 微信小程序基础库 ≥ 2.25；iOS/Android 主流机型；后台 Chrome/Edge 最新版 |
| **可维护** | ① 评测服务商做适配层封装，1 周内可切换供应商 ② schema 全字段 COMMENT ③ 强制 migration 工具 ④ 数据字典与 API 契约自动生成（见 `02` 文档 1.5） |
