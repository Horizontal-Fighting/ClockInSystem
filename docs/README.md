## 🔒 数据最小化原则（核心合规策略）

**学生档案只有昵称 + 系统预置头像**，不采集真实姓名、生日/年龄、性别、年级、学校、位置、真人照片、手机号。

> ⚠️ **但有一个躲不掉的例外：录音**。学生的声音属儿童个人信息，所以**监护人同意流程不能省**——这是最容易被误解的地方。详见 `02` 文档 7.0。
>
> 收益：敏感数据只剩录音一项 → 合规文本可以写得很短、审计范围从「全站台账」缩小到「录音生命周期」、法务过审成本大幅降低。

## 一页看懂这个项目

**一句话定义**：不是内容播放器，而是「布置 → 跟读 → AI 打分 → 教师点评 → 成长可见」的完整闭环工具。

**真正在解决的问题**：不是内容不够，而是孩子每天读、没人听、听不到反馈；老师要听 100 条录音，只能挑 10 条听。

**产品成立的前提**：用 AI 语音评测替掉教师重复性的听音劳动，让老师只做机器做不了的事（针对性点评、鼓励、纠偏），把「一个老师带 20 人」扩到「带 200 人」而教学质量不降。

## ⚠️ 规模修正：上一版的很多设计是过度设计

**已确认「总用户不超过几百」，这与我上一版按 1 万学员做的设计差两个数量级。** 以下设计已砍掉或下调：

| 原设计 | 处置 | 原因 |
|---|---|---|
| 表分区（PARTITION） | ❌ **移除** | 5 年才 330 万条，单表毫无压力 |
| 冷热分层 / 归档库 | ❌ **移除** | 数据量根本到不了需要归档的程度 |
| 读写分离 / 只读实例 | ❌ **移除** | 峰值 QPS < 1 |
| CDN 加速 | ❌ **移除** | 几百人流量，CDN 反而增加复杂度 |
| RabbitMQ / RocketMQ | ⭕ **降级为 Redis 队列** | 杀鸡用牛刀；保留队列只为防故障雪崩 |
| 4C8G × 2 服务器 | ⬇️ **降为 2C4G 单机** | 峰值 QPS < 1 |
| 双供应商适配 | ⭕ **只留接口，暂不接入讯飞** | 当前规模一年差价不到两千，不值得 |
| **并发成本** | ✅ **可忽略** | 峰值并发 < 3，远低于 50 的免费额度 |
| `raw_json` 压缩 + 保留期 | ✅ **保留**（顺手做） | 改造成本现在最低 |
| **tenant_id 隔离 + 越权测试** | ✅ **保留**（底线） | 与规模无关，SaaS 必备 |

**修正后的月度成本：约 ¥550 ~ 900**（评测 ¥150~313 + 服务器存储 ¥400~600）。

> 判断原则：**几百用户的系统，架构复杂度的危害远大于数据量本身。** 单机单库意味着 AI 维护时出错概率和排查难度都显著下降。

## 本轮新增的四个关键结论

### 1. 语音评测：腾讯云和讯飞是同一量级，其他家高一个数量级

| 供应商 | 本项目场景单价 | 结论 |
|---|---|---|
| 腾讯云智聆 | **3.25 ~ 5 元/千次** | 主选 |
| 讯飞 | 2 ~ 6 元/千次 | 备选，规模过万时比腾讯便宜约 38% |
| Azure | ¥4.7 ~ 9.4 / 音频小时 | 成本不最差，但**合规排除** |
| 驰声 | 23 ~ 27 元/千次 | 考试级，日常打卡用不值 |

**最容易算错账的地方**：国内按**调用次数**计费，Azure 按**音频时长**计费。短音频（2 秒）两者接近，但段落朗读（40 秒）按次计费便宜 **10 倍以上**。我们的场景短内容占 80%，按次计费优势明显。

### 2. 成本真正该防的不是单价，是重录和并发

- 重录系数从 1.6 涨到 4.0，成本翻 **2.6 倍** → 产品限 10 次 + 服务端风控
- 腾讯云超 50 并发收 ¥30/个/月，规模上来后**并发费可能与调用费相当** → 架构上必须 MQ + 令牌桶削峰

### 3. 多租户最致命的风险是「数据串号」

一处漏写 `tenant_id`，A 机构就能看到 B 机构的孩子和录音——这是 SaaS 的致命事故，也是 AI 生成代码最容易犯的错。

防法：ORM 层自动注入（不接受前端传参）+ 索引强制 tenant_id 打头 + **CI 里放一个跨租户越权自动化测试**。

补充一个真实场景：**一个家长可能报多家机构**，所以 user ↔ tenant 是多对多，不能想当然设计成一对一。

### 4. 数据库最大的隐藏地雷是 `raw_json`

评测原始 JSON 含音素级明细，单条 2-4KB。1 万学员规模下**每年 26-53 GB**，三年可达 160 GB，会拖垮备份和主从复制。

解法：**压缩行格式**（降到 1/5）+ **6 个月后只留结构化字段、清空 raw_json**。理由很简单——raw_json 只用于近期调参回标和供应商切换时重解析，远期价值几乎为零。

> 好消息：**三年内不需要分库分表**。靠表分区 + 预聚合表 + 冷热分层即可支撑 1 万学员。过早引入分库分表会让 AI 维护成本陡增，能不做就不做。

## 6-12 岁 vs 3-6 岁：产品设计的三个调整

| 调整 | 说明 |
|---|---|
| 分两个学段 | 6-8 岁拼读筑基（L1-L4），9-12 岁句型与阅读（L5-L9）。一年级和六年级用同一套东西必然有一头不讨好 |
| 排行榜从 P2 提到 P1 | 这个年龄段**同伴驱动效果显著**，但要支持机构级开关，且默认不显示低分者 |
| 反馈可以更直接 | 小学生能接受"这句没读好，再来一次"，阈值可以比幼儿严格，不需要极力避免任何负面信号 |

> ⚠️ 但合规没有放松空间：6-12 岁**全部属于「不满 14 周岁」儿童范畴**，儿童个人信息全套要求一个都不能少。
