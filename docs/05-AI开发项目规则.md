# AI 开发项目规则

> **用法**：建代码仓库时，把本文件复制为项目根目录的 `CLAUDE.md`（或 `.cursorrules` / `.github/copilot-instructions.md`），AI 编码工具会自动读取。
> 本文件是**喂给 AI 的第一份、也是最重要的一份上下文**——它存在的目的是防止 AI 在长期迭代中写出互相矛盾的代码。
> 版本：V1.0 ｜ 2026-09-16

## 0. 给 AI 的第一句话

你正在开发一个**面向 6-12 岁儿童的英语拼读打卡小程序（多租户 SaaS）**。用户是培训机构，核心闭环是：

```
老师布置任务 → 学生听范读 → 录音 → AI 打分 → 老师点评 → 打卡日历 / 统计
```

**在写任何代码之前，请先读这三份文档**（它们是需求的唯一真相来源）：
- `docs/01-产品需求说明书PRD.md` — 做什么
- `docs/02-技术架构与数据设计.md` — 怎么存、怎么设计
- `docs/04-开发启动前检查清单.md` — 当前决策状态

**如果你发现代码与文档冲突，以文档为准，并向人类提出，不要自己改文档。**

## 2. 🔴 红线清单（违反即返工）

以下每一条都是**硬约束**，写代码时逐条对照：

| # | 红线 | 为什么 |
|---|---|---|
| R1 | **禁止从任何前端请求参数（query/body/header）读取 `tenant_id`** | 租户隔离的命门。tenant_id 只能由网关/拦截器从登录态注入。漏一处就是 A 机构看到 B 机构的孩子和录音 |
| R2 | **禁止在 `student` 表新增任何敏感个人信息字段** | 已确认数据最小化。真实姓名/生日/性别/年级/学校/位置/照片/手机号**一律不许加** |
| R3 | **禁止硬编码评分权重、星级阈值、ScoreCoeff** | 教研会反复调。全部走 `sys_config` 或 `level` 表配置 |
| R4 | **评测失败不得阻断打卡** | 录音先落库，评测异步重试，失败转人工点评。**第三方故障绝不能让孩子打不了卡** |
| R5 | **音频访问必须走临时签名 URL**（有效期 ≤ 2h），COS 桶私有读 | 儿童录音泄露是重大事故 |
| R6 | **禁止对学生录音做任何声纹识别 / 说话人辨认 / 生物特征提取** | 合规红线，避免落入生物识别最高监管等级 |
| R7 | **禁止给"环境类问题"打低分** | 低分时先查音量与完整度：离麦太远 ≠ 发音差。提示重录，**不给低龄孩子打低分** |
| R8 | **禁止删除 `guardian_consent` 记录** | 只追加不可删，是合规举证凭证 |
| R9 | **禁止在代码里写魔法数字** | 所有枚举必须定义常量并注释（见 §7） |
| R10 | **删除学生必须级联真删 COS 音频对象** | 只删数据库记录 = 数据没删干净，合规风险 |
| **R11** | **禁止 `new PrismaClient()`** | 全应用只能注入 `PRISMA` token（见 `common/prisma/prisma.module.ts`）。自己 new 的客户端**没有租户隔离扩展**，等于裸奔 |
| **R12** | **禁止使用 `findUnique` / `findUniqueOrThrow`** | 它按唯一键查，无法注入 `tenantId`，是越权主要来源。Prisma 扩展里已直接抛错，**一律改用 `findFirst`** |
| **R13** | **禁止在业务代码里手写 `tenantId` 查询条件** | 由扩展自动注入。业务代码里出现 `tenantId:` 通常意味着架构被绕过了 |
| **R14** | **禁止 `new PrismaClient()` 之外的 raw SQL 绕过**：`$queryRaw` 不走租户扩展 | 必须写 raw SQL 时（复杂统计），**自己带上 `tenant_id = ?`**，并在注释里说明原因 |

> **R11~R14 的落地位置**：`apps/server/src/common/tenant/prisma-tenant.extension.ts`。
> 想了解自动注入的完整逻辑，直接读那个文件，不要凭猜。

## 3. 多租户隔离规范（★ 本项目最容易出事的地方）

### 3.1 隔离方案
**共享库共享表 + `tenant_id` 行级隔离**。`tenant_id = 0` 保留给平台公共数据（如公共素材库）。

### 3.2 强制约束

1. **所有业务表必须包含 `tenant_id` 列**（`sys_config` 等配置表也含，0 为全局默认）。
2. **所有查询必须带 `tenant_id` 条件**——由 ORM 拦截器/全局 scope 自动注入，**不允许业务代码手写**。
3. **联合索引必须以 `tenant_id` 打头**，例如 `(tenant_id, student_id, due_date)`。
4. **写入时 `tenant_id` 从登录态自动填充**。
5. **跨租户越权自动化测试是 CI 必跑项**：造两个租户的数据，断言 A 租户的所有查询都拿不到 B 租户的任何一行。**这个测试不通过，不允许合并代码。**

### 3.3 已落地实现（M1，2026-09-17）

多租户底座已实现，**后续所有业务代码直接依赖，不要另起炉灶**：

| 文件 | 职责 |
|---|---|
| `common/tenant/tenant-context.ts` | `AsyncLocalStorage` 存 tenantId。用上下文传递而非手动传参，从源头消灭"漏写" |
| `common/tenant/prisma-tenant.extension.ts` | ★核心。Prisma 扩展，拦截所有含 `tenantId` 模型的操作并自动注入。含 `findUnique` 禁用与 create 覆盖逻辑 |
| `common/tenant/tenant.middleware.ts` | 从 **JWT** 解析 tenantId 建立上下文（只认服务端签发的 token，不接受请求参数）。用 middleware 而非 interceptor，避免 RxJS 异步丢失上下文 |
| `test/cross-tenant.e2e-spec.ts` | 6 个用例：越权查详情 404、列表互不可见、伪造 tenantId 无效、未登录 401、`findUnique` 被禁用 |

**新增业务表时你只需要做两件事**：① 在 `schema.prisma` 里加 `tenantId` 字段和索引；② 正常写业务代码。
隔离是自动的——**不需要、也不应该**在业务代码里碰 tenantId。
6. `user` ↔ `tenant` 是**多对多**（一个家长可能报多家机构），走 `user_tenant` 表，**不要设计成一对一**。
7. 扫码加入班级时，**必须校验登录用户所属租户与二维码所属租户一致**，否则会出现跨机构串班。
8. 管理后台（平台侧）操作租户数据时，同样走 `tenant_id`，只是可以切换。

## 4. 数据库约定

### 4.1 通用规则

- 每张表、每个字段**必须写 `COMMENT`**，枚举值在注释里列全（例：`status: 1在读 2请假 3结业 4流失`）
- 主键：`bigint`，`checkin_item` / `media_file` 用**雪花 ID**，其余可用自增
- 所有表含 `created_at` / `updated_at`；**软删除仅在有恢复需求的表使用**
- 时间与日期字段统一 `datetime`，存储 UTC 或统一时区（**二选一后全局一致，不要混**）
- 金额/分数统一 `decimal(5,2)`
- **所有 schema 变更必须走 migration 文件，禁止直接改表或依赖 synchronize**

### 4.2 核心表清单（完整定义见 `02` 文档第 3 章）

```
tenant / user / user_tenant / tenant_usage
student / guardian_consent / class_group / group_member / level
material / material_pack / pack_item
courseware / courseware_block / courseware_progress
task / task_target / checkin_record / checkin_item
media_file / score_detail / review
notification / operation_log / sys_config / daily_class_stat
```

### 4.3 数据最小化（合规硬约束）

**`student` 表只允许这些业务字段**：`nickname`（昵称）、`avatar_preset`（预置头像编号）、`level_id`、`parent_user_id`、`teacher_remark`（教师备注）、`pin_hash`、`base_score`、`status`。

**已被明确删除、不得恢复**：`birthday`、`gender`、`grade`、`avatar_url`、真实姓名。

> 评分严格系数**由 `level.score_coeff` 推导，不依赖学生年龄**（因为不采集生日）。

小程序端**不得申请**以下权限：`getLocation`、`getPhoneNumber`、`chooseImage`（头像场景）、相机。

## 5. 语音评测规范

### 5.1 适配层（必须）

评测能力**必须封装在独立 service 中**，对外暴露统一接口：

```ts
interface SpeechEvalProvider {
  evaluate(audio: Buffer, refText: string, mode: EvalMode, opts: EvalOptions): Promise<EvalResult>;
}
```

**业务代码禁止直接调用腾讯云 SDK**，否则未来切换供应商要改全站。

### 5.2 已知坑（必须处理）

- **必须用新版（1774，WebSocket），禁用基础版（884，REST）**。两者是独立产品、资源包不通用，
  基础版即将下线。基础版 SDK 是 `tencentcloud-sdk-python-soe`，**不要安装、不要 import**。
  新版 SDK 无 PyPI 包，官方源码已置于 `spike/_soesdk/`（被 gitignore）。
- `PronAccuracy` 返回 **0~100**；**`PronFluency` 和 `PronCompletion` 返回 0~1 浮点，必须 ×100 归一化**
  （新版实测同样如此）。忘了这一步，流利度权重会被吃掉两个数量级——这是接入时最常见的 bug。
- **新版 `result` 是 Go 结构体字符串**（`{SuggestedScore:88.5 PronAccuracy:91.2 ...}`），**不是 JSON**，
  需专门解析。参考 `spike/soe_new.py` 的 `parse_result()`。
- **★ 评分消息的位置不要想当然**。官方注释说「`final=1` 那条不含 `result`、数据在它前一条」，
  但 2026-09-17 实机跑出来的结果是**分数就在 `final=1` 那条里**，只监听 intermediate 会拿到空。
  正确做法：**intermediate 和 final 都监听，谁有 `result` 用谁**（`soe_new.py` 里已这样实现）。
  这类「文档与实际不符」的地方以实测为准。
- **`SpeakingAssessment` 没有 `set_score_coeff()` 方法**，`score_coeff` 是普通属性，直接赋值。
  另外官方源码的 `on_close(ws)` 与新版 websocket-client 的三参数回调不兼容，需改成 `on_close(ws, *args)`。
- **`start()` 内部会 print 带 signature 的完整 URL**，生产代码里必须屏蔽 stdout，否则签名串漏进日志。
- 新版需要 **AppID + SecretId + SecretKey** 三个凭据，AppID 与 SecretId 是两回事。
- **排错优先级**：先 `--check` 自检把问题收敛到「凭据 / 服务开通 / 音频」三者之一，
  再去看代码。不要一上来就怀疑参数写错。

### 5.3 综合分公式（权重进配置，不写死）

| 内容类型 | 公式 |
|---|---|
| 单词 | `score = Accuracy` |
| 句子 | `0.6×A + 0.25×F + 0.15×C` |
| 段落 | `0.5×A + 0.3×F + 0.2×C` |
| 儿歌 | 同段落，但完整度权重更低 |

星级阈值与 `ScoreCoeff` 从 `level` 表读取（`level.score_coeff` / `level.star_threshold`）。

### 5.4 两条兜底（必须实现）

1. **低分先判环境**：`volume_avg` 过低 或 `completion` 过低 → 判定「离麦太远 / 没读完」，提示重录，**不计入低分统计**。
2. **评测失败不阻断**：先进 Redis 重试队列，重试仍失败 → 标记 `eval_status=4` 并转人工点评队列。

### 5.5 成本控制

- 单条目最多 **10 次**录音（服务端计数 + 风控）
- 无效音频前置拦截（< 0.5s / 纯静音）→ **直接拒绝，不调用评测**
- 评测请求**统一进 Redis 队列 + 令牌桶限速**，不要来一个请求调一次

## 6. API 约定

- 风格：**RESTful**，路径见 `02` 文档第 4 章
- 统一响应体：`{ code: number, message: string, data: any }`，`code = 0` 表示成功
- 错误码分段：`4xxxx` 业务错误 / `5xxxx` 系统错误，**每个错误码必须登记**
- 所有写操作**必须幂等**（评测、提交打卡尤其重要）
- 分页参数统一 `page` / `pageSize`，返回 `total`
- **列表接口默认带租户过滤**，分页上限 100
- 敏感操作（导出、删除、查看录音）**必须写 `operation_log`**

## 7. 代码风格

### 7.1 命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 数据库表/字段 | snake_case | `checkin_item`, `due_date` |
| TS 变量/函数 | camelCase | `getTodayTasks` |
| TS 类/接口/枚举 | PascalCase | `CheckinService`, `EvalMode` |
| 常量 | UPPER_SNAKE | `MAX_RETRY_COUNT` |
| 小程序页面目录 | kebab-case | `pages/checkin-detail/` |
| 枚举字段 | 数字 + 常量 | `CheckinStatus.SUBMITTED = 2` |

### 7.2 禁止魔法数字

```ts
// ❌ 错误
if (record.status === 2) { ... }

// ✅ 正确
export enum CheckinStatus {
  PENDING = 1,    // 待打卡
  SUBMITTED = 2,  // 已提交（待点评）
  REVIEWED = 3,   // 已点评
  REDO = 4,       // 需重做
  DONE = 5,       // 已完课
}
if (record.status === CheckinStatus.SUBMITTED) { ... }
```

**所有状态、类型、模式必须有枚举常量 + 注释。**

### 7.3 其他

- 函数单一职责，超过 60 行考虑拆分
- 禁止吞掉异常（`catch` 里必须记录日志或向上抛）
- 关键路径必须有日志（评测调用、文件上传、删除操作）
- **禁止提交任何密钥到仓库**；配置走环境变量
- 类型定义共享：后端 DTO 与前端类型通过 `shared/` 目录复用，不要各写一份

## 8. 合规红线（儿童个人信息）

1. **监护人同意**：创建学生档案时**必须**弹出《儿童个人信息处理规则》单独勾选（**不可默认勾选、不可与其他条款捆绑**），同意记录写入 `guardian_consent`（版本、时间、IP、UA）。
2. **即使只收集昵称，监护人同意也不能省**——因为录音属于儿童声音，仍是个人信息。这是最容易误解的一点。
3. **录音保留期 12 个月**，到期前后台提醒，不做自动硬删除。
4. **删除能力**：注销/撤回同意 → 级联删除 `checkin_item` → `media_file` → **COS 对象真删**。
5. **不做声纹识别**，并在用户条款中明确声明。
6. 与评测服务商的协议必须含：不得留存、不得用于模型训练、处理完毕即删除。
7. 儿童数据的查询/导出/删除操作全部进 `operation_log`，保留 ≥ 3 年。

## 9. Definition of Done（功能完成的判定标准）

一个功能只有满足以下全部才算完成：

- [ ] 符合 PRD 中对应条目的描述（逐条对照，不增不减）
- [ ] **所有数据库查询带 `tenant_id`**（且不是从前端传的）
- [ ] 新增/修改的表与字段有 `COMMENT` + migration 文件
- [ ] 枚举有常量定义，无魔法数字
- [ ] 错误场景有兜底（尤其是：评测失败、上传失败、第三方超时）
- [ ] 敏感操作写了 `operation_log`
- [ ] 涉及儿童数据的路径已过一遍 §8 合规清单
- [ ] 有对应的测试用例（**跨租户越权测试是必跑项**）
- [ ] 没有引入文档未提及的新依赖

## 10. AI 协作约定

1. **不确定的地方先问，不要猜**。尤其是业务规则和数据模型——猜错的代价远高于问一次。
2. **不要自作主张扩大范围**。用户让你做 A，不要顺手把 B 也做了（"顺手优化"是 AI 迭代产生冲突代码的主要来源）。
3. **文档与代码冲突时，停下来提给人类**，不要自己改文档、也不要擅自按代码来。
4. **重要决策写进 ADR**（`docs/adr/NNNN-决策标题.md`），记录「决策 + 理由 + 被否决的方案」，防止后续迭代推翻已有设计。
5. **改数据模型前必须先确认**——schema 变更的影响面远大于业务代码。
6. 每次完成一个模块，简要说明：改了哪些文件、有没有偏离文档、有什么遗留问题。

## 11. 当前不要做的事（明确排除）

| 不要做 | 原因 |
|---|---|
| 分库分表 / 表分区 / 读写分离 | 几百用户规模，过度设计 |
| CDN、RabbitMQ/Kafka、Elasticsearch | 同上 |
| 接入讯飞等第二家评测商（**适配层要留，但暂不接入**） | 规模太小，差价不够覆盖维护成本 |
| 视频课程 / 视频存储转码 | 已确认课件只做文字 + 语音 |
| 租户自助注册与在线付费 | 机构由人工开通 |
| 学生独立账号体系 | 已确认家长/学生共用账号（预留 `student.user_id` 即可） |
| 任何生物识别（人脸/声纹） | 合规红线 |
