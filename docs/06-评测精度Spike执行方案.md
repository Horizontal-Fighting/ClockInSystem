# 评测精度 Spike 执行方案

> 目标：**在写第一行业务代码之前，验证「AI 打的分，老师认不认」**
> 周期：3 个工作日（+ 前置半天准备）
> 成本：**几毛钱**（约 100-200 次评测调用），不需要服务器、不需要小程序
> 状态：可执行

---

## 0. 一页纸 TL;DR

| 项 | 内容 |
|---|---|
| **做什么** | 录 30+ 条 6-12 岁儿童真实英语发音 → 老师盲评打分 → AI 打分 → 对齐差异 |
| **为什么** | 语音评测是本项目最大不确定性。若 AI 评分老师不认可，后续所有功能都白做 |
| **怎么做** | Day1 采集录音 → Day2 跑 AI + 双师盲评 → Day3 统计分析与校准 |

| **产出** | 校准后的权重参数（直接写进 `sys_config`）、Go/No-Go 决策、可复用的评测脚本 |
| **前置条件** | 腾讯云账号 + SOE 开通 + 一台能跑 Python 的电脑 + 手机录音 |

## 1. 为什么必须先做这个

### 这个项目真正的风险不在技术难度，在「分数是否可信」

产品承诺的是「自动打分 + AI 纠音」。但这个分数会：

- 直接展示给孩子和家长（**打低了打击积极性，打高了失去意义**）
- 决定星级、积分、升级（**分数不可信 = 整个激励体系崩塌**）
- 被老师看到（**老师不认可，就不会用，产品推不动**）

而语音评测对儿童发音的准确度，恰恰是所有厂商都含糊其辞的地方——官方文档只会说「高准确度」，不会告诉你**在 6-12 岁中国儿童、带环境噪音、手机录制**的条件下到底准不准。

**这个 Spike 就是把「不知道」变成「有数字」。**

### 三个必须现在做、不能等到 M2 的理由

1. **成本极低**（几毛钱 + 3 天），但能砍掉项目最大的不确定性
2. **结论会改变设计**：如果 AI 精度不够，产品形态要变（比如改为「AI 只给参考、星级由老师定」），晚发现就是返工
3. **顺带产出校准参数**：文档 `02` 里的评分权重现在是拍脑袋给的，Spike 后要用真实数据拟合出来

## 2. 成功与失败判定标准（Go / No-Go）

### 2.1 通过（GO）—— 需同时满足

| # | 指标 | 阈值 | 说明 |
|---|---|---|---|
| 1 | **Pearson r** | **≥ 0.75** | AI 分与人工分线性相关。低于此值说明排序都不对 |
| 2 | **MAE（平均绝对误差）** | **≤ 8 分** | 之前定的核心指标 |
| 3 | **人类基线对照** ★ | **AI-人工 MAE ≤ 1.3 × 教师A-教师B MAE** | 见下方说明，**这条比第 2 条更本质** |
| 4 | **星级一致率** | **≥ 70%** | AI 星级与老师星级完全一致的占比 |
| 5 | **音素错误命中率** | **≥ 60%** | 老师标出的错误音素，出现在 AI 返回的最低分音素 Top3 中 |
| 6 | **坏样本识别率** | **≥ 80%** | 6 条「环境/态度问题」样本中，至少 5 条能被判定需重录 |

### 2.2 ★ 关键方法论：先测「人类基线」，再谈 AI 准不准

这是本方案最重要的一点，**也是最容易被忽略的一点**。

如果只有一位老师打分，你永远不知道「AI 差 8 分」到底是 AI 不准，还是**人类评分本身就存在 8 分的波动**。真实的口语评分本来就是主观的——同一条录音，两位有经验的老师给出 82 和 90 完全正常。

所以：

```
1. 先让两位老师独立打分，算出「教师A vs 教师B」的 MAE 和 r  → 这是人类基线
2. 再算「AI vs 教师平均分」的 MAE 和 r
3. 判断标准不是绝对误差，而是：
      AI 的误差 是否 落在 人类评分者之间的误差 范围内
```

**如果 AI-人工 的误差 ≈ 人-人 的误差，说明 AI 已经达到「相当于再多请一位老师」的水平** —— 对这个产品而言，这就够了，就是 GO。

反过来，如果人-人 MAE = 4 分，而 AI-人工 MAE = 12 分，那即使 AI 绝对分看起来「还行」，也说明它明显不如人，**不能当作自动评分用**。

> 这条判断准则请务必传达给参与评分的老师，否则他们会问「AI 差 8 分到底行不行」，而这个问题单独看是没有答案的。

### 2.3 不通过时的分级应对（提前想好，避免当场慌）

| 失败模式 | 含义 | 应对 |
|---|---|---|
| **r 高（≥0.75）但 MAE 大** | 排序对，但有系统性偏差（如 AI 整体偏高 10 分） | ✅ **可修**。用线性回归校准即可，脚本会自动给出校准公式。**这是最常见也最好的失败模式** |
| **r 中等（0.6~0.75）** | 大致可用但不够稳 | ⚠️ 降低 AI 权重：AI 分只做参考，星级与升级由老师确认；或只在单词模式用 AI，句子/段落转人工 |
| **r 低（< 0.6）** | AI 连排序都排不对 | ❌ **严重**。换供应商（讯飞 ISE）重跑一次 Spike（约 2 天）；仍不行则产品改为「AI 只做音素诊断、不打分」 |
| **音素命中率低（< 60%）** | 「AI 纠音」这个卖点不成立 | ⚠️ 产品定位调整：去掉音素级纠错展示，改为只给总分 + 老师人工纠音。**不要对外宣称做不到的功能** |
| **坏样本识别不了** | 离麦远/噪音会被误判成发音差 | ✅ **可修**。补规则：音量 < 阈值 或 完整度 < 阈值 → 判定环境问题，提示重录而非给低分（这正是 `02` 文档里的兜底设计） |

## 4. 样本设计（录什么）

### 4.1 总量与结构：建议 30-36 条

**8-12 个孩子 × 每人 3-4 条**。低于 25 条统计不稳定，高于 40 条老师会疲劳导致评分质量下降。

### 4.2 内容分布

| 类型 | 条数 | EvalMode | 作用 |
|---|---|---|---|
| **A · 单词** | 12 | `0` | 最核心场景（自然拼读），也是 AI 最容易准的类型 |
| **B · 短句** | 12 | `1` | 6-10 词，含连读与句调 |
| **C · 段落** | 6 | `2` | 30-50 词，验证长内容表现（预计最不准） |
| **D · 坏样本** ★ | 6 | 混合 | 见下，**必做**，用于验证兜底逻辑 |

### 4.3 内容选择原则：覆盖中国孩子的典型发音难点

不要随机选词，**刻意覆盖这些易错音**（这是 6-12 岁中国学生的高频错误）：

| 难点 | 示例词 |
|---|---|
| /θ/ /ð/ | thin, three, this, that |
| /æ/ vs /e/ | cat, bag, bad |
| /v/ vs /w/ | van, wet, very |
| /l/ /r/ 混淆 | red, leg, light |
| /ʃ/ /s/ | ship, fish, she |
| 词尾辅音吞音 | dog(t), big(g), cat(t) |
| 词尾 -s / -ed | books, cats, played, wanted |
| 双音节重音 | about, happy, teacher |

**每个孩子都要覆盖不同难点**，不要 12 个孩子都读 cat。

### 4.4 ★ D 类坏样本（6 条，最容易被跳过但价值高）

这 6 条用来验证一个关键设计：**打出低分时，先看是不是环境问题（离麦太远/噪音），而不是发音差，然后提示重录——绝不给低龄孩子打低分。**

| # | 场景 | 期望系统行为 |
|---|---|---|
| D1 | 离麦克风 50cm 远 | 识别为环境问题，提示「靠近一点再试」 |
| D2 | 开着电视/背景音乐 | 识别为噪音，提示换个安静地方 |
| D3 | 故意很小声（耳语） | 音量过低，提示大声一点 |
| D4 | 家长在旁边提示/抢答 | 识别为多人声，提示重录 |
| D5 | 读到一半停顿 5 秒再继续 | 流利度低但准确度可能正常 → 判断是否需要重录 |
| D6 | 读到一半放弃（只读前 1/3） | 完整度极低 → 提示「没读完哦，再试一次」 |

> **★ 坏样本请用句子模式（`eval_mode=1`）**：单词模式下「流利度/完整度」返回 -1（无意义），
> 而 D5/D6 的判定恰恰依赖完整度。用单词模式录坏样本，会拿不到判据，这 6 条就白录了。
>
> 这 6 条不参与相关性计算（它们不是"正常发音样本"），单独统计**识别率**。
> 判定的量化依据：脚本会输出每条的 `completion`（完整度）、`duration`、AI 分，人工对照找出阈值。

### 4.5 学生水平分布

由老师事先把孩子分成 **高 / 中 / 低** 三档（各 3-4 人），记录到 `samples.csv` 的 `level` 列。

**必须有低水平样本** —— 全是好学生会让所有分数挤在高分区，相关系数会虚高或失效（统计上叫「范围受限」）。

## 5. 人工评分规范（★ 决定 Spike 成败）

### 5.1 三条铁律

1. **盲评**：打分前不得看 AI 分数，不得看另一位老师的分数
2. **随机顺序**：脚本会生成随机播放顺序，两位老师用**各自不同的随机顺序**（防顺序偏差）
3. **固定量规**：按下面的 rubric 打，不要凭感觉

### 5.2 评分量规（发给老师）

老师对每条录音只需给 **3 个值**，控制负担才能保证质量：

**① 总分（0-100 整数）**

| 区间 | 标准 |
|---|---|
| 90-100 | 发音清晰准确，几乎没有可察觉的错误；流畅自然 |
| 80-89 | 整体正确，有 1-2 个轻微音素偏差，不影响理解 |
| 70-79 | 能听懂，但有明显发音错误（如 /θ/ 读成 /s/），或有明显卡顿 |
| 60-69 | 多数词能辨认，但错误较多，需要费力听 |
| < 60 | 大量音素错误，或基本没读出来 |

**② 星级（1-3 星）** —— 按你心目中「这个孩子值不值得鼓励」来打

**③ 最明显的 1-2 个发音错误音素**（文本形式填写，如 `th`、`ae`）
- 用 **智聆音素写法**（见下表），否则脚本匹配不上
- 如果这条没有明显错误，填 `无`

| 常见音 | 智聆写法 |
|---|---|
| /θ/ | `th` |
| /ð/ | `dh` |
| /æ/ | `ae` |
| /ʃ/ | `sh` |
| /ʒ/ | `zh` |
| /ŋ/ | `ng` |
| /tʃ/ | `ch` |
| /dʒ/ | `jh` |

> ⚠️ **æ 不能直接写**，智聆音素里用 `ae`。这是文档明确要求的，写错了匹配不上。

### 5.3 打分环境建议

- 用耳机听（手机外放会丢细节）
- 每条可重复听，但**不超过 3 遍**（避免越听越纠结）
- 中途休息，一次连续打分不超过 20 条（疲劳会显著放大评分波动，污染人类基线）

## 6. 三天日程

### Day 1 · 采集录音（1 天）

| 时间 | 事项 |
|---|---|
| 上午 | 8-12 个孩子录音。**★ 必须用家长的手机录，不要用电脑麦克风或录音笔** —— 采集设备必须与真实使用场景一致，否则结果偏乐观 |
| 午间 | 导入电脑，**逐条听一遍**，剔除明显无效的（没录上、全静音） |
| 下午 | **转码**（见 §7.1）→ 命名 → 填 `samples.csv` |

**录制备忘**：
- 安静房间，手机距离孩子 **20-30cm**
- 每条读完停顿 1 秒再停录（避免截断尾音）
- 优先录 wav，或 m4a/mp3 后转码
- 记录每个孩子的水平档位（高/中/低）

### Day 2 · 跑 AI + 双师盲评（1 天）

| 时间 | 事项 |
|---|---|

| 下午 | 两位老师各自盲评（用脚本生成的不同随机顺序）。**先人工评，后对 AI 分** —— 顺序不能反，否则被锚定 |

### Day 3 · 分析与决策（1 天）

| 时间 | 事项 |
|---|---|
| 上午 | 跑 `analyze.py` → 看相关系数、MAE、人类基线、分层表现、音素命中率、坏样本识别 |
| 下午 | 若存在系统性偏差 → 用脚本给出的**校准公式**修正 → 复核指标 → 出 Go/No-Go 结论 |

**Day 3 产出（必须落到文档）**：

1. 校准后的综合分公式与权重 → 回填 `02-技术架构与数据设计.md` §2.5
2. 各学段/级别的 `ScoreCoeff` 与星级阈值
3. 音素纠错是否可用的结论 → 影响 PRD 中 F3-8/F3-9 的优先级
4. 坏样本判定阈值（音量/完整度/时长）
5. Go / No-Go 决策

## 7. 工具使用

脚本在 `spike/` 目录。

### 7.1 转码（★ 必须做，最容易踩的坑）

**腾讯云要求：16k 采样率 / 16bit / 单声道。** 手机录的通常是 44.1k 或 48k 立体声，**不转码会直接导致评测不准或失败**，且这个错误很隐蔽——接口不报错，只是分数不对。

```bash
# 单个文件
ffmpeg -i input.m4a -ar 16000 -ac 1 -sample_fmt s16 output.wav

# 批量（当前目录下所有 m4a/mp3）
mkdir -p wav16k
for f in *.m4a *.mp3; do
  [ -e "$f" ] || continue
  ffmpeg -i "$f" -ar 16000 -ac 1 -sample_fmt s16 "wav16k/${f%.*}.wav"
done

# 验证（必须是 16000 Hz, mono, s16）
ffprobe -hide_banner wav16k/xxx.wav 2>&1 | grep -E "Stream"
```

### 7.2 填样本清单

编辑 `spike/samples.csv`：

```csv
sample_id,audio_file,ref_text,eval_mode,group,level,student_id,note
A01,wav16k/A01.wav,cat,0,word,high,S01,
A02,wav16k/A02.wav,thin,0,word,mid,S01,
B01,wav16k/B01.wav,"I have a big red bag.",1,sentence,mid,S02,
C01,wav16k/C01.wav,"The sun is shining...",2,paragraph,high,S03,
D01,wav16k/D01.wav,cat,0,bad,mid,S01,离麦50cm
```

- `eval_mode`：`0` 单词 / `1` 句子 / `2` 段落
- `group`：`word` / `sentence` / `paragraph` / `bad`
- `level`：`high` / `mid` / `low`

### 7.3 跑 AI 评测

```bash
cd spike

# 凭据写在 .env 里（推荐），或临时 export：
#   export TENCENTCLOUD_APPID="1306xxxxxx"
#   export TENCENTCLOUD_SECRET_ID="xxx"
#   export TENCENTCLOUD_SECRET_KEY="xxx"

python run_eval.py --check      # ★ 先自检：不需要录音文件，验证凭据+服务开通
python run_eval.py --limit 1    # 有录音后，先跑 1 条验证端到端
python run_eval.py              # 全量跑
# 输出：results.csv + raw/*.json

# 音频路径无需额外指定：脚本会自动兼容 A01.wav / wav16k/A01.wav 两种写法
```

`--check` 和 `--limit 1` 这两步**不要跳过**。接口不通（AppID 漏填、服务未开通、音频格式错）时，
早发现比批量跑完才发现好。批量失败一次要浪费资源包次数。

> **预算提醒**：默认对每条样本跑 3 组 `ScoreCoeff`（1.0 / 1.5 / 2.5），
> 36 条样本 = 108 次调用。若只想先看趋势，`--coeff 1.0` 可降到 36 次。

### 7.4 人工打分

## 8. 统计方法说明（给想看懂数字的人）

| 指标 | 用途 |
|---|---|
| **Pearson r** | 线性相关。看 AI 分与人工分是否同涨同跌 |
| **Spearman ρ** | 等级相关。**比 Pearson 更重要** —— 因为星级是按排名切分的，只要排序对，星级就准 |
| **MAE** | 平均绝对误差，直观：AI 分与人工分平均差多少分 |
| **Bias + Bland-Altman** | 揭示**系统性偏差**。若 AI 整体偏高 3 分，r 可能很好但绝对值不对 → 用校准修 |
| **分层分析** | 按内容类型（单词/句子/段落）、水平（高/中/低）分别看。**往往单词很准、段落很不准**，需要分开定权重 |
| **最小二乘回归** | 拟合 `人工分 ≈ a×准确度 + b×流利度 + c×完整度 + d`，**用数据算出权重，替代拍脑袋** |

### 为什么用回归拟合权重，而不是直接调整

因为「权重该是多少」本质是：AI 的三个维度，哪个更能预测老师的判断。**回归直接回答这个问题，且给出可解释的系数。**

拟合后要检查 R² 和系数合理性（比如出现负系数，说明该维度与人工判断相悖，需要单独分析）。

## 9. 常见坑（按踩中概率排序）

| # | 坑 | 后果 | 规避 |
|---|---|---|---|
| 1 | **没转码**（44.1k/立体声） | 分数整体偏低或忽高忽低，**接口不报错** | §7.1 转码后必须 ffprobe 验证 |
| 2 | **老师看了 AI 分再打** | 被锚定，人类基线虚高，Spike 结论无效 | 严格盲评，AI 结果 Day 3 才给老师看 |
| 3 | **`PronFluency`/`PronCompletion` 是 0~1 浮点** | 忘了 ×100，流利度权重被吃掉两个数量级 | 脚本已处理；自己写代码时务必注意 |
| 4 | 样本全是好学生 | 分数挤在高分区，相关系数失效 | 必须有 low 档样本 |
| 5 | 用电脑麦克风录音 | 结果偏乐观，上线后真实数据打脸 | 必须用手机录 |
| 6 | 一位老师打分 | 无法计算人类基线，MAE 无参照 | 至少 2 位 |
| 7 | 老师连续打分 40 条 | 疲劳导致评分漂移，污染基线 | 每 20 条休息 |
| 8 | `ScoreCoeff` 不试多组 | 错过最优参数 | 脚本默认跑 1.0/1.5/2.5 三组 |
| 9 | 段落超 30 词 | 句子模式有 30 词限制 | 段落用 EvalMode=2 |
| 10 | 音素写成国际音标 `æ` | 匹配不上，命中率假性为 0 | 用智聆写法 `ae` |
